# Купить в один клик: кнопка на странице товара + модальное окно

**Для кого:** фронтенд (volt12-client).
**Что делаем:** на странице товара рядом с основной кнопкой «В корзину» — заметная
кнопка «Купить в один клик». По нажатию открывается небольшое модальное окно с
минимумом полей. Полное оформление заказа (адрес, доставка, оплата) не проходим —
менеджер перезванивает и уточняет остальное.

> **Статус бэкенда:** ручка `POST /volt12/quick_order` реализована и проверена
> локально; на прод уедет ближайшим деплоем — бэкенд отпишется, когда она будет
> доступна на `80.93.61.63:8000`. Контракт ниже — финальный, меняться не будет.

---

## Ручка

### `POST /volt12/quick_order`

Публичная — авторизация **не требуется**. Запрос отправлять с
`credentials: 'include'`, как остальные ручки: если пользователь авторизован,
бэкенд сам привяжет заказ к его аккаунту.

**Тело запроса:**

```jsonc
{
  "catalog_item_id": 59,                  // обязательно, id товара со страницы
  "quantity": 1,                          // опционально, по умолчанию 1 (1..99)
  "name": "Иван",                         // обязательно
  "phone": "+7 (999) 123-45-67",          // обязательно
  "email": "ivan@example.com",            // обязательно
  "comment": "перезвоните после 18:00",   // опционально, до 1000 символов
  "agree_policy": true                    // обязательно, должно быть true
}
```

**Успех — `201`:**

```jsonc
{ "success": true, "order_id": 124 }
```

**Ошибки** — формат тот же, что у `/volt12/feedback` и `/volt12/booking`:

```jsonc
{ "success": false, "errors": ["phone is invalid", "email is required"] }
```

| Код | Когда | Что показать |
|-----|-------|--------------|
| `400` | не прошла валидация, см. таблицу ниже | подсветить конкретные поля |
| `404` | `catalog_item not found` — товара нет или он снят с публикации | «Товар больше не доступен», окно закрыть |
| `429` | лимит 10 отправок в час с одного IP | «Слишком много запросов, попробуйте позже» |
| `500` / сеть | всё остальное | «Не удалось отправить заявку, попробуйте ещё раз» |

Полный список строк в `errors`, на которые нужно мапить поля:

| Строка ошибки | Поле |
|---|---|
| `catalog_item_id is required`, `catalog_item not found` | — (общая ошибка окна) |
| `quantity is invalid` | количество |
| `name is required`, `name is invalid` | имя (`is invalid` — длиннее 255 символов) |
| `phone is required`, `phone is invalid` | телефон |
| `email is required`, `email is invalid` | email |
| `comment is invalid` | комментарий (длиннее 1000 символов) |
| `agree_policy is required` | чекбокс согласия |
| `Too many requests` | — (общая ошибка окна) |

Ошибки приходят массивом — их может быть несколько за один ответ, разложить все
сразу, а не только первую.

Отправка писем на ответ не влияет: если заказ сохранён, приходит `201` даже когда
письмо не ушло (лимит или сбой почты) — заказ уже виден менеджеру в админке.
Поэтому `429` означает ровно одно: слишком часто жмут кнопку с этого IP.

### `GET /volt12/auth/me` — префилл

Ручка уже есть, менять её не нужно. Если пользователь авторизован, подставить в
окно его имя, телефон и email (поля остаются редактируемыми). Неавторизованному
показываем пустую форму. Отдельного запроса ради окна делать не надо — страница
товара уже знает про пользователя.

### Данных о товаре достаточно тех, что уже есть

Название, цена и картинка для «шапки» окна берутся из ответа
`POST /volt12/catalog_items/detail`, который страница товара уже получила.
Дополнительных запросов нет.

## Поля окна

| Поле | Обязательное | Правила |
|------|--------------|---------|
| Имя | **да** | от 2 до 255 символов после `trim` |
| Телефон | **да** | маска `+7 (___) ___-__-__`; валидно, если после удаления всего кроме цифр остаётся 11 цифр и первая — `7` или `8` |
| Email | **да** | обычная проверка формата, до 255 символов |
| Комментарий | нет | textarea, до 1000 символов |
| Количество | нет | целое 1..99, по умолчанию 1; если на странице товара уже есть счётчик — брать значение из него |
| Согласие с политикой | **да** | чекбокс со ссылкой на политику; пока не отмечен — кнопка отправки `disabled` |

Телефон отправляем **как ввёл пользователь**, вместе с маской — бэкенд сам
приводит к `+7XXXXXXXXXX`. Нормализовать на фронте не нужно.

Валидацию делаем на фронте до отправки (мгновенная подсветка), но ответ `400`
всё равно обрабатываем — бэкенд валидирует независимо.

## Поведение

1. **Кнопка** «Купить в один клик» — рядом с «В корзину», заметная (по макету),
   на том же уровне иерархии. Доступна всегда, когда товар можно купить:
   если основная кнопка «В корзину» заблокирована (товара нет), блокируем и эту.
2. **Открытие окна** ничего не отправляет на бэкенд и **не трогает корзину** —
   товар в корзину не добавляется ни до, ни после отправки. Это отдельный
   сценарий, корзина остаётся как была.
3. **Отправка:** кнопку перевести в состояние загрузки и заблокировать до ответа.
   Повторный клик не должен уходить вторым запросом — идемпотентности на бэкенде
   нет, два запроса создадут два заказа.
4. **Успех:** в том же окне показать экран «Заявка принята» с номером заказа
   (`order_id`) и текстом, что менеджер перезвонит для подтверждения. Окно
   закрывается по кнопке/оверлею. Поля формы после успеха очищаем — если
   пользователь откроет окно снова, он начинает с чистой формы (кроме префилла
   для авторизованного).
5. **Что происходит дальше** (для понимания, фронту делать нечего): заказ падает
   в админку в раздел «Заказы» со статусом «Новый» и источником `quick`, менеджеру
   уходит письмо, покупателю — письмо-подтверждение на указанный email.
6. **Авторизованный пользователь** увидит такой заказ в личном кабинете
   (`GET /volt12/orders`) наравне с обычными. Важно: у заказа «в один клик»
   **пустые поля адреса** (`city`, `region`, `street`, `house`, `postal_code`,
   `apartment`, `entrance` — пустые строки или `null`). Экран «Мои заказы» и
   карточка заказа должны это переживать — не рисовать «, , » и пустые строки
   адреса. Если сейчас там безусловная склейка адреса, её надо поправить.
7. **Мобильная версия:** окно должно нормально жить на узком экране (клавиатура
   перекрывает половину высоты) — скролл внутри окна, кнопка отправки видима.
8. Запрос — только на клиенте, в SSR не вызывать.
