# Страница товара: три блока связанных товаров вместо «Вам может понравиться»

**Для кого:** фронтенд (volt12-client).
**Что случилось:** блок «Вам может понравиться» (автоподбор по похожести названия) удалён.
Вместо него бэкенд отдаёт **три** блока, которые контент-менеджер наполняет вручную в админке.

---

## ⚠ Breaking change

В ответе `POST /volt12/catalog_items/detail` **больше нет ключа `related`**.
Вместо него три новых ключа: `recommended`, `bought_together`, `also_needed`.
Если фронт продолжит читать `related`, получит `undefined` — блок просто перестанет
рендериться, ошибок не будет. Но код, завязанный на `related`, надо удалить.

---

## Формат ответа

`POST /volt12/catalog_items/detail` — тело запроса не менялось (`{"slug": "...", "recently_viewed_ids": [...]}`).

Ответ (показаны только изменившиеся части):

```jsonc
{
  "success": true,
  "item": { /* как раньше, без изменений */ },

  // НОВОЕ: три блока, каждый — массив карточек
  "recommended":     [ /* карточки */ ],   // блок «Рекомендуемые товары»
  "bought_together": [ /* карточки */ ],   // блок «С этим товаром покупают»
  "also_needed":     [ /* карточки */ ],   // блок «Вам также может понадобиться»

  "recently_viewed": [ /* как раньше, без изменений */ ]
}
```

### Формат карточки

Точно такой же, как был у `related` и как сейчас у `recently_viewed` —
существующий компонент карточки переиспользуется без изменений:

```jsonc
{
  "id": 42,
  "name": "Popular product 4",
  "slug": "asdasd",
  "price": 12000,
  "img_link": "uploads/items/xxx.webp"   // может быть null!
}
```

- `img_link` — относительный путь, склеивать с `apiBase` как обычно
  (`${apiBase}/${img_link}`). **Может быть `null`** — товар без картинок в эти
  блоки попадать может (как раньше в «похожие»). Нужен плейсхолдер.
- `price` — целое, в рублях (как везде).

---

## Правила отображения

1. **Три отдельных блока** с заголовками:
   - `recommended` → **«Рекомендуемые товары»**
   - `bought_together` → **«С этим товаром покупают»**
   - `also_needed` → **«Вам также может понадобиться»**
2. **Пустой массив — блок не рендерим вообще** (ни заголовка, ни пустой сетки).
   Пока админ ничего не привязал, все три массива пустые — это нормальное состояние,
   автоматического подбора больше не существует.
3. **Порядок карточек уже правильный** — бэкенд сортирует по позиции, которую админ
   задал перетаскиванием. На фронте ничего не сортировать.
4. **Количество не ограничено.** Раньше `related` был максимум из 4 штук; теперь
   сколько админ привязал — столько и придёт. Если карточек много, решаем на фронте:
   карусель/скролл/обрез сеткой — на усмотрение дизайна (бэкенд резать не будет).
5. Один и тот же товар может встретиться в нескольких блоках одновременно — это ок.
6. Бэкенд сам скрывает неопубликованные и «пандоровские» товары — дополнительной
   фильтрации на фронте не нужно.

## Рекомендуемый порядок блоков на странице

Сверху вниз: «Рекомендуемые товары» → «С этим товаром покупают» →
«Вам также может понадобиться» → «Вы смотрели» (recently_viewed — там, где и был).

## Откуда данные берутся (для понимания)

В админке три новых раздела (Каталог → «Рекомендуемые товары», «С этим товаром
покупают», «Также может понадобиться»). Каждая запись — связка «товар → товар»
с позицией. Дубли пар, привязка товара к самому себе и конфликт позиций
блокируются на бэкенде. Таблицы в БД: `catalog_item_recommendations`,
`catalog_item_bought_together`, `catalog_item_also_needed`.
